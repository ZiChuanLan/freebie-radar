# AI 二审接入（MG / mercury-3）

## 起因

用户指出推送里混进了这两条：

```
88% 受访开发者点头赞成：FreeBSD 组建工作组制定 AI 使用新规     rss-ithome · 68 分
谁有ovh 年付10%优惠券哇                                  NodeSeek · 60 分
```

一个是科技新闻，一个是求优惠券的提问帖。规则（关键词 + 打分）永远补不完，得上语义判断。

## 配置

`.env`（服务器 `/opt/freebie-radar/.env`）：

```bash
AI_BASE_URL=https://mg.zichuanlan.top/v1
AI_API_KEY=<MG 的 key>
AI_MODEL=mercury-3
AI_MAX_ITEMS=60
```

`config.ts` 里 `aiEnabled = Boolean(aiBaseUrl && aiModel)`，网关是 OpenAI 兼容的 `/chat/completions`，所以换任何兼容端点都行。

## 提示词

`src/server/enrich/ai.ts` 的 SYSTEM_PROMPT 把判定标准写死成两类，关键是**能明确说出「能拿到什么」**：

**keep=true**：直接领取的免费软件/游戏喜加一、注册就送的额度/体验金/会员天数、有明确数量的赠送（送 N 个、抽 N 份）、兑换码/邀请码、限时开放注册、免费教育资源包。

**keep=false**：新闻资讯政策解读（点名了「某组织制定 AI 使用新规」）、求助提问求优惠券、纯讨论吐槽测评、二手交易/账号共享/盗版、只是打折但需实付（>5 元）、广告推广。

输出 `{"index","keep","category","reason"}` 数组，`reason` 限 20 字中文。

分批：每批 20 条，`aiMaxItems` 内全部送审（不是只审前 N 条）。

## 三处生效

1. **入库时**（`collectors/index.ts`）：每轮采集的新条目送审，日志打 `[源] AI 二审 N 条，判定非福利 M 条`；判非福利的 score 打五折。
2. **推送时**（`push.ts`）：`FreshItem.aiKeep === false` 直接不推 —— 攒批和立即推都拦。
3. **历史补审**（`cli.ts ai-review [limit]`）：AI 上线前的存量条目没有结论，必须补审，否则老数据照样会被推出去。

```bash
docker compose exec -T radar node --no-warnings node_modules/tsx/dist/cli.mjs src/server/cli.ts ai-review 900
```

## 规则兜底（AI 之外）

AI 有延迟和成本，所以 `enrich/noise.ts` 里也补了正则，作为第一道闸：

- 提问类：`谁有|求个|求购|哪有|哪里有|多少钱|求助|求带|求推荐|大佬|老哥|有人吗|怎么弄`
- 新闻类：`受访|工作组|新规|研究表明|报告显示|调查显示|统计显示|宣布|组建|规划|白皮书|开发者大会`
- 既有：`致歉|股价|油价|冲突|送医|受伤|事故|判刑|被捕|辞职|解散|阵容|转会|投诉|维权|涨价|降价|跌破|市值|财报|营收|裁员|上市|权益价|万元|车型`

`URGENT`（手慢无信号）也收紧了：删掉裸的 `送`、`抢`、`限时`、`最后`，改成 `送\s*\d+\s*(个|份|张|枚|次)`、`送码`、`送体验金`、`限时免费`。

> 教训：`URGENT` 里一个裸「送」字，把「球迷头部受伤**送**医」推成了「⚡ 新羊毛 · 限量/限时」。
